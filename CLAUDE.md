# RentFlow

Веб-приложение для арендодателей: распределение коммунальных платежей
по арендаторам и выставление им счетов.

## Стек
- Django, Python 3.13, Windows.
- БД: локально SQLite, на сервере PostgreSQL.
- Модули в `apps/`: accounts, properties, tenants, billing, payments.
  Все расчёты — только в `services.py` каждого модуля, с тестами.
- Библиотеки: django-environ (.env), django-allauth (вход), HTMX,
  свой CSS с переменными (минимализм, цвет #34495e + акцент #148f77), Ruff.

## Два региона из одной кодовой базы
- Россия (пилот, сначала) и ЕС (потом) — одна кодовая база, две отдельные установки.
- Разница задаётся переменной `REGION=ru/eu` в `.env`.
- Деньги — только `Decimal` + явная валюта, никогда float.
- Все тексты пользователю — через переводы Django (ru, en), не хардкод строк.
- Оплата и вход — через сменные «переходники» (адаптеры), чтобы заменить
  провайдера под регион без переписывания бизнес-логики.

## Продукт и дизайн
- Для «ленивого арендодателя»: максимум минимализма, всё понятно без инструкций.
- 4 шага (и девиз): объект → арендаторы → квитанции и счётчики → честный расчёт.
  Шаги 1–3 делаются один раз, шаг 4 каждый месяц.
- Название RentFlow для обоих регионов. Акцент только #148f77 (не терракотовый).
- Деление расхода: разово, по долям, поровну или по м².
- Каркас: тёмная полоса с иконками + сворачиваемое меню + шапка (`templates/app/base.html`).
- Главная — «Объекты»: переключатель месяца, 4 карточки сводки, карточки объектов
  (адрес, УК, телефон остаются на карточке — нужны для быстрого доступа).
- Окно «Новый объект» / «Изменить объект» (модальное, `static/js/app.js`): блок «Объект и УК / ТСЖ»
  + блок «Кто пользуется объектом» (арендаторы или собственник). Доли вводятся в % или в м² —
  переключатель на весь объект; вторая единица считается через площадь объекта
  (`apps/tenants/services.py`), в БД хранятся обе. Пароль от кабинета УК не храним — только подсказку.
- Стиль окон: каждый блок в рамке (`.form-section` в forms.css — рамка, скругление 12px,
  серая шапка с заголовком КАПСОМ). Так во всех окнах: объект, просмотр, арендаторы, «Новая услуга».
  Плитки-шаблоны (`.kind-tile`) и строки «К какому объекту?» — в рамке; «уже есть» — галочка.
  Безрамочный вариант «А» пробовали 2026-11-08 и откатили — пользователю больше нравятся рамки.
- Все формы одинаковые: подпись всегда НАД полем (12px), поле 38px (`.fl` в `static/css/forms.css`, шаблон
  `templates/properties/_field.html`, блок «Compact windows» в конце forms.css), фокус — акцент. Кнопки окон 38px.
  Плотные отступы: внутри блока 12px, между рядами 10px, между блоками 12px; ссылки «Информация об УК», «+ Добавить …» — 13px. Свой календарь для дат,
  свои выпадающие меню («Тип», % / м²), подсказки «?» карточкой. Enter — следующее поле.
- Меню «…» на карточке: «Посмотреть» (сводная карточка), «Изменить», «Удалить» (подтверждение) —
  всё во всплывающем окне. После сохранения/удаления — список объектов и уведомление вверху.
- После создания объекта — окно «Остался один шаг» (`_created.html`): «Позже» / «Добавить квитанции».
- Меню слева: «Объекты» → «Квитанции и счётчики» → «Счета» → «Справочники» → «Отчёты».
  Пункты «+ Добавить …» в меню — акцентным цветом.
- Квитанции и счётчики — один шаг: счётчик это свойство квитанции («свет — по счётчику»).
- Страница объекта: 2/3 — данные объекта, квитанции и показания за месяц;
  1/3 — расчёт по арендаторам (у пользователя есть заготовка логики расчёта).

## Рабочий процесс
- Работа с двух компьютеров через Git: pull в начале, commit + push в конце.
- Интерфейс: сначала концепт в чате, затем каждый блок/окно — в своей ветке
  `feature/...`, в `main` вливаем готовое. Claude сам подсказывает, когда открыть ветку.
- После pull с миграциями: `python manage.py migrate`.
- Команда `/form-designer-pro` — навык проекта (`.claude/skills/form-designer-pro/SKILL.md`):
  разбор формы и лаконичный вариант по правилам форм RentFlow. Появляется в новой сессии.
