# RentFlow

Веб-приложение для арендодателей: распределение коммунальных платежей по арендаторам и выставление им счетов.
Пользователь учится: объяснять коротко, по-русски, строго в рамках текущего шага.

## Стек
- Django 6, Python 3.13, Windows. БД: локально SQLite, на сервере PostgreSQL.
- Модули в `apps/`: accounts, properties, tenants, billing, payments. Все расчёты — только в `services.py` модуля, с тестами
  (`apps/billing/tests.py`, `test_*.py`; сейчас 227 тестов, все зелёные).
- Библиотеки: django-environ (.env), django-allauth (вход), HTMX, fpdf2 (PDF счёта), свой CSS с переменными, Ruff (не установлен).
- Свой JS без фреймворков: `static/js/app.js` (один IIFE), `static/js/formula.js` (окно «Своя формула»).
- Стили: `static/css/base.css`, `app.css`, `forms.css`, `billing.css` (большой; блоки по экранам, новые — в конец), `formula.css`.
- Стили/скрипты подключаются с `?v=<хэш>` (`config/context_processors.static_version`) — кэш браузера не мешает.
- Шрифты PDF: `static/fonts` — Roboto (основной), DejaVu Sans (знаки, которых нет в Roboto, например «→»).

## Два региона из одной кодовой базы
- Россия (пилот) и ЕС (потом) — одна кодовая база, две установки; `REGION=ru/eu` в `.env`.
- Деньги — только `Decimal` + явная валюта, никогда float.
- Все тексты пользователю — через переводы Django (ru, en). Пока тексты в шаблонах без переводов — долг.
- Оплата и вход — через сменные адаптеры под регион.

## Рабочий процесс
- Работа с двух компьютеров через Git: pull в начале, commit + push в конце. Git по SSH (HTTPS режет корпоративный фильтр).
- Каждый блок/окно — в своей ветке `feature/...`, в `main` вливаем готовое. Claude сам подсказывает, когда открыть ветку.
- После pull: `.venv\Scripts\python.exe -m pip install -r requirements.txt` и `python manage.py migrate` (миграции billing до 0028).
- Сервер: preview `django` из `.claude/launch.json` (localhost:8000).
- Интерфейс: сначала концепт/макет (`docs/mockups/*.html`, открыть в браузере), потом код. Макеты — только для истории идей.
- `/form-designer-pro` — навык проекта (`.claude/skills/form-designer-pro/SKILL.md`): разбор формы по правилам RentFlow.
- Многострочный `{# … #}` в шаблонах Django не работает — только однострочный или `{% comment %}`.

## Правила пользователя (важно)
- **Ровно.** Перед показом любой страницы/окна/PDF измерить, что левые и правые края всех блоков совпадают, отступы
  одинаковые. «Каждая строка не своей ширины», «кривые зубы» — главные претензии.
- **Минимализм для «ленивого арендодателя»**: всё понятно без инструкций; лишние слова, подсказки и строки убирать.
- **Компактнее — не значит меньше размером.** Плотность — за счёт порядка, а не мелкого шрифта.
- Цвет: основной #34495e, акцент только #148f77. Не пёстро: цветные только иконки и важные числа.
- Два кружка рядом не ставить (номер в кружке + иконка в кружке).
- **У одного счётчика — одно поле ввода на странице объекта, никогда два.**
- **Один счётчик — одна услуга — один тариф** (формула может только читать расход).
- Счётчик принадлежит помещению; арендатора на счётчик сажает услуга («Кто платит»). Счётчик вне услуг — всегда «Общий».
- Стандартные UX-мелочи делать без просьбы (показ пароля, подсказки и т.п.).

## Дизайн-система
- Каркас: тёмная полоса с иконками + сворачиваемое меню + шапка (`templates/app/base.html`). Меню запоминает открытые
  разделы (`rentflow.navOpen` в localStorage).
- Меню: Объекты → Услуги (Все услуги, Тарифы, + Добавить услугу) → Счётчики (Все счётчики, + Добавить) → Оплаты → Счета →
  Справочники → Отчёты. «+ Добавить …» — акцентным цветом.
- Окна модальные (`data-modal`, заголовок `X-Modal`, ответ `X-Modal-Redirect`); после сохранения — назад на страницу,
  откуда открыли (Referer), уведомление вверху.
- Блоки окон: `.form-section` — рамка, скругление 12px, серая шапка КАПСОМ; внутри 10px под шапкой и над рамкой, 8px между строками.
- Поля: подпись над полем, поле 38px (`.fl`, `templates/properties/_field.html`), фокус — акцент. Кнопки окон 38px, справа,
  «Отмена» слева от главной (`.form-actions`). Свой календарь, свои выпадающие меню, «?» — подсказка карточкой. Enter — следующее поле.
- Поля для ЧИСЕЛ: бледно-жёлтые только пока пустые (`--input-warm`, `:placeholder-shown`), после ввода белые; коэффициент
  всегда белый. Единица внутри поля («5 200 ₽», `.num-wrap`/`.num-unit`). Числа при вводе делятся по разрядам.
- Переключатели `.seg-track` (выбранное — заливка акцентом), да/нет — `.switch`, метки `.badge` (`-info/-ok/-warn/-danger`).
- Длинные названия не переносятся, а затухают (`.fade`).
- Таблицы «Все услуги», «Тарифы», «Все счётчики» — один стиль `.svc-table` (колонка «Объект», иконка 34px, метки `.tag`,
  одинаковые ширины столбцов, меню «…» с «Изменить» / «Удалить»; узкий экран — карточки). Строка открывает окно услуги.
- Цвета видов счётчиков: электричество #0e9aa7, холодная вода — синий, горячая — красный, отопление — оранжевый,
  газ — фиолетовый, свой — серый (иконки в `METER_ICONS` app.js / `_meter_icon.html`).

## Модель данных (apps/billing/models.py)
- `Property` (properties): название, адрес, площадь, УК (пароль не храним, только подсказку), доли в % или м².
- `Tenant` (tenants): имя, `share_percent` и площадь (хранятся обе единицы, вторая считается через площадь объекта).
- `Meter` — счётчик объекта: вид (`kind`), имя, №, единица, `day_night`, начальные показания, `tenant` (SET_NULL),
  `vacant` (арендатор съехал — платит собственник), `input_mode` (Было/стало или Расход; пусто — как у услуги).
- `Receipt` — услуга («Услуга» в интерфейсе): вид, название, поставщик, начисление (`amount_mode`: по квитанции / фиксированная /
  по площади `RATE` / по счётчикам `metered` / своя формула `FORMULA`), `split` (по долям / поровну / по м² / по расходу /
  по счётчикам / плачу сам), `excluded` (кто не платит), `coefficient`, `night_weight`, `meters` (M2M), `position` (порядок карточек),
  `formula` (JSON блоков).
- `ReceiptTariff` — тарифы услуги с историей «с месяца» (ключи `m:<meter>`, вид, `*`, `rate:area|person`, `num:<id>`).
  Новый тариф — с текущего месяца, прошлые месяцы по старому.
- `MonthlyAmount` (сумма квитанции за месяц), `Reading` (показания: previous/current, ночь, usage).
- `FormulaNumber` / `FormulaValue` — числа «Своей формулы» (тариф/норматив или «каждый месяц»).
- `ServiceTemplate` — свои плашки владельца (только у своего объекта).
- `Payment` — оплата поставщику: услуга × месяц, `paid_on`, `note` (120), `note_carry`.

## Расчёт (apps/billing/services.py)
- `month_bill(property, month)` — всё для страницы объекта за месяц: `entries` (ввод), `payers` (счета арендаторов), `owner`
  («Остаётся на вас»), `missing`, `readings_done/total`. Копейки ROUND_HALF_UP; остаток округления и незанятая доля — собственнику;
  коэффициент умножает только счета арендаторов. «Было» = прошлое «стало» или начальное показание. «Стало» < «было» —
  как не введено (красная точка).
- По счётчикам: каждый платит по своему счётчику; общие счётчики и счётчики арендаторов в одной услуге не смешиваем.
- По расходу (`_usage_split`): сумма квитанции × расход счётчика / общий расход; ночь может весить меньше (`night_weight`, «н×0,6»).
- По площади: тариф × м² объекта или × чел. (люди вводятся в окне услуги).
- Своя формула: `apps/billing/formula.py` — вычислитель без eval, Decimal, проверка единиц (итог в ₽; «-» = без единицы).
  Счётчик в формуле — только подключённый к услуге «По счётчикам»/«По расходу»; нет показаний — услуга не считается.
- Счёт: `bill_groups` («Общие · по долям 45%» / «По счётчикам»), `bill_meter_rows` («счётчик № …», «251 → 255 = 4 кВт·ч ×
  9,5 ₽ = 38,00 ₽», день/ночь отдельно), `money_words` (сумма прописью), `bill_text`, `bill_file_name`.
- Оплаты: `payment_table` (объекты × НАЗВАНИЯ услуг, одноимённые складываются), `save_payment`, `save_payment_note`,
  перенос пометки (`_inherited_notes`).

## Экраны (что есть сейчас)
- **Объекты** (`/properties/`): переключатель месяца, 4 карточки сводки, карточки объектов (адрес, УК, телефон; «услуги ·
  показания · начисления» настоящими числами за месяц; блоки «Услуги ✎»/«Арендаторы ✎» — иконка после подписи).
  Меню «…»: Посмотреть / Изменить / Удалить.
- **Окно объекта**: Объект (поля УК свёрнуты под «Информация об УК ▾») → Счётчики (плашки `.meter-tiles`, «+ Добавить счётчик» —
  маленькое окно) → Кто пользуется (арендаторы строками, маленькое окно на одного). Удалить счётчик, по которому считается
  услуга, нельзя — окно «Счётчик привязан к услуге». После создания — окно «Остался один шаг».
- **Окно услуги** (опрос): плашки-шаблоны (Ком. услуги, Электричество, Вода гор., Вода хол., Интернет, свои, «Своя») →
  «Услуга» (Название в счёте, Поставщик) → «Начисление» — 5 плашек (По квитанции · Фиксированная · По площади · По счётчикам ·
  Своя формула) + серая панель-ответ → «Делим» и арендаторы с «платит / не платит» или строки счётчиков (тариф, «Кто платит»,
  «Ввод», вкл.). Своя плашка — переключатель «Сохранить как плашку». Кнопка «Сохранить услугу».
- **Окно «Своя формула»** (`formula.js`): палитра («Вводите каждый месяц», «Тарифы и нормативы», счётчики, знаки), строка
  формулы с перетаскиванием, примеры, «Как посчитается» по арендаторам.
- **Страница объекта** (`/properties/<id>/`): слева данные объекта и плательщики (sticky); в центре «Ввод за месяц» —
  компактный ввод для всего объекта (`services.month_input`): «Суммы из квитанций» (метка-акцент «за весь объект»),
  «Показания счётчиков» (столбцы Было / Стало / Расход в серой шапке, группа на услугу со своим фоном цвета вида 5%,
  день/ночь одно под другим, «н×»), «Считается само» (суммы справа). После названия услуги — ✎ (`.head-icon`).
  Автосохранение, живой пересчёт, красная точка у невведённого, «⇅ Порядок» — перестановка строк. Справа (sticky
  `.obj-side`) — светлый блок «Чей счёт» (`.bill-switch`, арендаторы + «Остаётся на вас») и **Счёт** выбранного
  плательщика (вариант А): «СЧЁТ · НОЯБРЬ 2026», имя, метка «Готов к счёту» /
  «Не всё введено», группы в рамках, «Итого к оплате» + прописью, кнопки «PDF» · «Посмотреть» (PDF в модальном окне) ·
  значок «Поделиться» (WhatsApp, Telegram, копировать текст; на телефоне — отправить сам PDF).
- **PDF счёта** (`apps/billing/pdf.py`, вид `bill_print`: `/properties/<id>/bill/<id арендатора или 0>/?month=…`,
  `&inline=1` — показать): A4, поля 22 мм, Roboto, текст 6pt, только чёрный и серый, весь текст по одной левой/правой границе,
  без «RentFlow» и без суммы в шапке. Имя файла «Счёт ноябрь 2026 — Аптека Вита.pdf».
- **Все услуги** (`/services/`), **Тарифы** (`/tariffs/`, только услуги с тарифом), **Все счётчики** (`/meters/`, «Изменить»
  или «Создать услугу», «Удалить» с проверкой).
- **Оплаты** (`/payments/`): платежи владельца поставщикам. Одна таблица объекты × услуги, ячейка 100×46: сумма · галочка
  (оплачено сегодня) · дата (правится календарём) или «не оплачено» · «?» пометка (окно: текст + «Переносить на следующий
  месяц»; красный «?» — пометка есть). Справа «Итого» по объекту (ширина постоянная — таблица не прыгает), над таблицей
  серая полоса «Октябрь: не оплачено N» (красные только числа) — отмечается прямо там.

    `fx_new` (`formula_context`).
  - Слева «Начисление» (клик = новая услуга), «Услуги объекта». Справа шапка (название, поставщик, ✎; справа только «Есть несохранённые изменения» или ошибка — без «Сохранено» и 🗑),
    внизу полоса «Удалить услугу» (красный текст слева) · «Сохранить»; 🗑 и «Удалить» спрашивают в маленьком окне тут же;

    изменения»; ушли на другую услугу / начисление — окно «Сохранить изменения?» («Не сохранять» слева · «Отмена» — остаться · «Сохранить»).
    **Название и Поставщик — обязательные** (`*`, сервер: «Введите поставщика.»). Внизу: «Удалить услугу» слева,
    справа «Отмена» (закрыть без сохранения) · «Сохранить». Закрыли окно после сохранения — страница перезагружается.
    «+ Добавить счётчик объекта» → окно объекта → после «Сохранить»/«Отмена» назад в окно услуг с тем же введённым
    (черновик `window.rentflowServiceDraft`, ссылка `data-svc-return`, app.js `returnToService` → `openModal(get)`);
    новый счётчик того же вида сразу в таблице («Выберите»).
  - «Остаётся на вас»: `Receipt.owner_takes` (вкл — доля неплатящих на собственнике, «поровну» = ÷ всех; выкл — делят
    платящие). Так же у общего счётчика (`Meter.owner_takes`).
  - По тарифу: `Receipt.rate_unit` (м², чел., м³, своя) + `volume` (пусто + м² — площадь объекта), история — ReceiptTariff
    (`tariff` + `volume`). Свои единицы — из услуг владельца; × только у добавленных в этот раз.
  - **Группы счётчиков (решение пользователя, 2026-11-20): каждое название = группа.** Меню «Что меряет»: Электричество,
    Вода холодная, Вода горячая, Газ (`MENU_METER_KINDS`) + «свой вариант…»; счётчик со своим названием — своя группа
    («custom:<имя>»), на странице объекта её фон серый (`.mi-meters.rk-custom` #f1f2f4), иконка — счётчик (`i-gauge`).
