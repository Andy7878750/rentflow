# RentFlow

Веб-приложение для арендодателей: распределение коммунальных платежей по арендаторам и выставление им счетов.
Пользователь учится: объяснять коротко, по-русски, строго в рамках текущего шага.

## Стек
- Django 6, Python 3.13, Windows. БД: локально SQLite, на сервере PostgreSQL.
- Модули в `apps/`: accounts, properties, tenants, billing, payments. Все расчёты — только в `services.py` модуля, с тестами
  (`apps/billing/tests.py`, `test_*.py`; сейчас 237 тестов, все зелёные).
- Библиотеки: django-environ (.env), django-allauth (вход), HTMX, fpdf2 (PDF счёта), свой CSS с переменными, Ruff (не установлен).
- Свой JS без фреймворков: `static/js/app.js` (один IIFE), `static/js/formula.js` (окно «Своя формула»).
- Стили: `static/css/base.css`, `app.css`, `forms.css`, `billing.css` (большой; блоки по экранам, новые — в конец), `formula.css`.
- Стили/скрипты подключаются с `?v=<хэш>` (`config/context_processors.static_version`) — кэш браузера не мешает.
- Шрифты PDF: `static/fonts` — Roboto (основной), DejaVu Sans (знаки, которых нет в Roboto, например «→»).

## Для кого (аудитория)
- Россия: собственники коммерческих помещений, которые сдают сами (аптека, кафе, салон в одном здании).
- **ЕС (особенно Нидерланды, 2026-11-24): хозяин своего дома, где живут несколько студентов** — у каждого своя комната,
  общие гостиная и кухня. Счета на весь дом (энергия, вода, интернет, муниципальные сборы) делятся между жильцами.
  Учитывать в интерфейсе, расчётах и на лэндинге ЕС.

## Два региона из одной кодовой базы
- Россия (пилот) и ЕС (потом) — одна кодовая база, две установки; `REGION=ru/eu` в `.env`.
- Деньги — только `Decimal` + явная валюта, никогда float.
- Все тексты пользователю — через переводы Django (ru, en). Пока тексты в шаблонах без переводов — долг.
- Оплата и вход — через сменные адаптеры под регион.

## Рабочий процесс
- Работа с двух компьютеров через Git: pull в начале, commit + push в конце. Git по SSH (HTTPS режет корпоративный фильтр).
- Каждый блок/окно — в своей ветке `feature/...`, в `main` вливаем готовое. Claude сам подсказывает, когда открыть ветку.
- После pull: `.venv\Scripts\python.exe -m pip install -r requirements.txt` и `python manage.py migrate` (миграции billing до 0029).
- Сервер: preview `django` из `.claude/launch.json` (localhost:8000).
- Интерфейс: сначала концепт/макет (`docs/mockups/*.html`, открыть в браузере), потом код. Макеты — только для истории идей.
- `/form-designer-pro` — навык проекта (`.claude/skills/form-designer-pro/SKILL.md`): разбор формы по правилам RentFlow.
- Многострочный `{# … #}` в шаблонах Django не работает — только однострочный или `{% comment %}`.

## Правила пользователя (важно)
- **Ровно.** Перед показом любой страницы/окна/PDF измерить, что левые и правые края всех блоков совпадают, отступы
  одинаковые. «Каждая строка не своей ширины», «кривые зубы» — главные претензии.
- **Минимализм для «ленивого арендодателя»**: всё понятно без инструкций; лишние слова, подсказки и строки убирать.
- **Компактнее — не значит меньше размером.** Плотность — за счёт порядка, а не мелкого шрифта.
- Цвет: основной #34495e, акцент только #148f77. Не пёстро: цветные только иконки и важные числа.
  **Третий цвет — медовый #f2b544** (бледный #fdf3dc, для текста #8a6100; с 2026-11-23 на лэндинге; в приложении — `--color-honey*` в base.css, пока только вспышка новой услуги в окне услуг):
  «медовое — то, что вводите вы, бирюзовое — то, что посчитал RentFlow». Никогда: кнопки, обычный текст на белом,
  иконки видов счётчиков, предупреждения/ошибки. Мелкий акцентный текст на белом — #117965 (у #148f77 контраст мал).
- Два кружка рядом не ставить (номер в кружке + иконка в кружке).
- **У одного счётчика — одно поле ввода на странице объекта, никогда два.**
- **Один счётчик — одна услуга — один тариф** (формула может только читать расход).
- Счётчик принадлежит помещению; арендатора на счётчик сажает услуга («Кто платит»). Счётчик вне услуг — всегда «Общий».
- Стандартные UX-мелочи делать без просьбы (показ пароля, подсказки и т.п.).

## Модель данных (apps/billing/models.py)
- `Property` (properties): название, адрес, площадь, УК (пароль не храним, только подсказку), доли в % или м².
- `Tenant` (tenants): имя, `share_percent` и площадь (хранятся обе единицы, вторая считается через площадь объекта).
- `Meter` — счётчик объекта: вид (`kind`), имя, №, единица, `day_night`, начальные показания, `tenant` (SET_NULL),
  `vacant` (арендатор съехал — платит собственник), `input_mode` (Было/стало или Расход; пусто — как у услуги).
- `Receipt` — услуга («Услуга» в интерфейсе): вид, название, поставщик, начисление (`amount_mode`: по квитанции / фиксированная /
  по площади `RATE` / по счётчикам `metered` / своя формула `FORMULA`), `split` (по долям / поровну / по м² / по расходу /
  по счётчикам / плачу сам), `excluded` (кто не платит), `coefficient`, `night_weight`, `meters` (M2M), `position` (порядок карточек),
  `formula` (JSON блоков).
- `ReceiptTariff` — тарифы услуги с историей «с месяца» (ключи `m:<meter>`, вид, `*`, `rate:area|person`, `num:<id>`).
  Новый тариф — с текущего месяца, прошлые месяцы по старому.
- `MonthlyAmount` (сумма квитанции за месяц), `Reading` (показания: previous/current, ночь, usage).
- `FormulaNumber` / `FormulaValue` — числа «Своей формулы» (тариф/норматив или «каждый месяц»).
- `ServiceTemplate` — свои плашки владельца (только у своего объекта).
- `Payment` — оплата поставщику: услуга × месяц, `paid_on`, `note` (120), `note_carry`.

## Расчёт (apps/billing/services.py)
- `month_bill(property, month)` — всё для страницы объекта за месяц: `entries` (ввод), `payers` (счета арендаторов), `owner`
  («Остаётся на вас»), `missing`, `readings_done/total`. Копейки ROUND_HALF_UP; остаток округления и незанятая доля — собственнику;
  коэффициент умножает только счета арендаторов. «Было» = прошлое «стало» или начальное показание. «Стало» < «было» —
  как не введено (красная точка).
- По счётчикам: каждый платит по своему счётчику; общие счётчики и счётчики арендаторов в одной услуге не смешиваем.
- По расходу (`_usage_split`): сумма квитанции × расход счётчика / общий расход; ночь может весить меньше (`night_weight`, «н×0,6»).
- По площади: тариф × м² объекта или × чел. (люди вводятся в окне услуги).
- Своя формула: `apps/billing/formula.py` — вычислитель без eval, Decimal, проверка единиц (итог в ₽; «-» = без единицы).
  Счётчик в формуле — только подключённый к услуге «По счётчикам»/«По расходу»; нет показаний — услуга не считается.
- Счёт: `bill_groups` («Общие · по долям 45%» / «По счётчикам»), `bill_meter_rows` («счётчик № …», «251 → 255 = 4 кВт·ч ×
  9,5 ₽ = 38,00 ₽», день/ночь отдельно), `money_words` (сумма прописью), `bill_text`, `bill_file_name`.
- Оплаты: `payment_table` (объекты × НАЗВАНИЯ услуг, одноимённые складываются), `save_payment`, `save_payment_note`,
  перенос пометки (`_inherited_notes`).
