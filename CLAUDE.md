# RentFlow

Веб-приложение для арендодателей: распределение коммунальных платежей
по арендаторам и выставление им счетов.

## Стек
- Django, Python 3.13, Windows.
- БД: локально SQLite, на сервере PostgreSQL.
- Модули в `apps/`: accounts, properties, tenants, billing, payments.
  Все расчёты — только в `services.py` каждого модуля, с тестами.
- Библиотеки: django-environ (.env), django-allauth (вход), HTMX,
  свой CSS с переменными (минимализм, цвет #34495e + акцент #148f77), Ruff.

## Два региона из одной кодовой базы
- Россия (пилот, сначала) и ЕС (потом) — одна кодовая база, две отдельные установки.
- Разница задаётся переменной `REGION=ru/eu` в `.env`.
- Деньги — только `Decimal` + явная валюта, никогда float.
- Все тексты пользователю — через переводы Django (ru, en), не хардкод строк.
- Оплата и вход — через сменные «переходники» (адаптеры), чтобы заменить
  провайдера под регион без переписывания бизнес-логики.

## Продукт и дизайн
- Для «ленивого арендодателя»: максимум минимализма, всё понятно без инструкций.
- 4 шага (и девиз): объект → арендаторы → квитанции и счётчики → честный расчёт.
  Шаги 1–3 делаются один раз, шаг 4 каждый месяц.
- Название RentFlow для обоих регионов. Акцент только #148f77 (не терракотовый).
- Деление расхода: разово, по долям, поровну или по м².
- Каркас: тёмная полоса с иконками + сворачиваемое меню + шапка (`templates/app/base.html`).
- Главная — «Объекты»: переключатель месяца, 4 карточки сводки, карточки объектов
  (адрес, УК, телефон остаются на карточке — нужны для быстрого доступа).
- Окно «Новый объект» / «Изменить объект» (модальное, `static/js/app.js`): блок «Объект и УК / ТСЖ»
  + блок «Кто пользуется объектом» (арендаторы или собственник). Доли вводятся в % или в м² —
  переключатель на весь объект; вторая единица считается через площадь объекта
  (`apps/tenants/services.py`), в БД хранятся обе. Пароль от кабинета УК не храним — только подсказку.
- Стиль окон: каждый блок в рамке (`.form-section` в forms.css — рамка, скругление 12px,
  серая шапка с заголовком КАПСОМ). Так во всех окнах: объект, просмотр, арендаторы, «Новая услуга».
  Плитки-шаблоны (`.kind-tile`) и строки «К какому объекту?» — в рамке; «уже есть» — галочка.
  Безрамочный вариант «А» пробовали 2026-11-08 и откатили — пользователю больше нравятся рамки.
- Все формы одинаковые: плавающие подписи (`.fl` в `static/css/forms.css`, шаблон
  `templates/properties/_field.html`), поле 52px, фокус — акцент. Свой календарь для дат,
  свои выпадающие меню («Тип», % / м²), подсказки «?» карточкой. Enter — следующее поле.
- Меню «…» на карточке: «Посмотреть» (сводная карточка), «Изменить», «Удалить» (подтверждение) —
  всё во всплывающем окне. После сохранения/удаления — список объектов и уведомление вверху.
- После создания объекта — окно «Остался один шаг» (`_created.html`): «Позже» / «Добавить квитанции».
- Меню слева: «Объекты» → «Квитанции и счётчики» → «Счета» → «Справочники» → «Отчёты».
  Пункты «+ Добавить …» в меню — акцентным цветом.
- Квитанции и счётчики — один шаг: счётчик это свойство квитанции («свет — по счётчику»).
- Страница объекта: 2/3 — данные объекта, квитанции и показания за месяц;
  1/3 — расчёт по арендаторам (у пользователя есть заготовка логики расчёта).

## Рабочий процесс
- Работа с двух компьютеров через Git: pull в начале, commit + push в конце.
- Интерфейс: сначала концепт в чате, затем каждый блок/окно — в своей ветке
  `feature/...`, в `main` вливаем готовое. Claude сам подсказывает, когда открыть ветку.
- После pull с миграциями: `python manage.py migrate`.
- Команда `/form-designer-pro` — навык проекта (`.claude/skills/form-designer-pro/SKILL.md`):
  разбор формы и лаконичный вариант по правилам форм RentFlow. Появляется в новой сессии.

## Текущая работа
- Готово и влито в `main`: каркас приложения, страница «Объекты»,

- Готово и влито в `main`: окно добавления/изменения объекта с арендаторами
  (модуль `apps/tenants`), правки окна, календарь, плавающие подписи во всех формах
  (в т.ч. вход/регистрация), просмотр и удаление во всплывающем окне, уведомления.
- Готово и влито в `main`: окно «Остался один шаг» после создания объекта, раздел меню
  «Квитанции и счётчики» (пункты пока заглушки; «Добавить квитанции» ведёт на страницу объекта).
- Готово и влито в `main` (ветка `feature/receipts-setup`): модуль `apps/billing` и страница объекта.
  - Модели: `Receipt` (вид, название, кому платим, счётчик да/нет, единица, тариф, как делить:
    по долям / поровну / по м² / по показаниям / «Плачу сам»; сумма каждый месяц разная или постоянная;
    коэффициент), `Meter` (у арендатора или общий), `MonthlyAmount`, `Reading` (миграции 0001–0003).
  - Готовые виды с пресетами (`PRESETS` в `apps/billing/services.py`): УК/ЖКУ, свет, вода, газ,
    интернет, капремонт, мусор, своя. Окна: выбор вида, настройка, удаление.
  - Страница объекта: слева данные объекта + плательщики, в центре суммы и показания за месяц
    (переключатель месяца, автосохранение с живым пересчётом, Enter — следующее поле,
    красная точка у невведённых), справа счёт выбранного арендатора с формулами.
  - Расчёт `month_bill`: копейки ROUND_HALF_UP, остаток округления и незанятая доля — собственнику;
    прошлое показание берётся из прошлого месяца. Коэффициент (НДС 1,2 или наценка) умножает
    только счета арендаторов, расход собственника считается без него.
  - Длинные названия/адреса не переносятся, а затухают (`.fade` в app.css). Этаж на карточке не показываем.
- В работе ветка `feature/add-service`: «Добавление услуги».
  - Сделано: в интерфейсе «Услуга» вместо «Квитанция» (модели и код остаются `Receipt`;
    «квитанция» осталась только там, где речь о бумажной квитанции). Раздел меню «Услуги»:
    «Все услуги» — таблица по всем объектам (`/services/`, при нехватке ширины — карточки),
    «+ Добавить услугу» — «К какому объекту?» (при одном объекте сразу выбор вида).
    Везде кнопки «+ Добавить услугу» (не «+ Услуга»), в т.ч. в меню «…» карточки.
    Карточка объекта: без чек-листа с галочками (только плашка «Настройка N из 3», пока не готово);
    под списком арендаторов одна строка: «+ Добавить арендатора» или «Изменить арендаторов» (если есть
    хоть один) — окно «Арендаторы · Объект» только с арендаторами (`property_tenants`).
    Блок цифр на карточке и странице объекта: три ровные колонки по центру с перегородками —
    число крупно, подпись мелко: «услуги · показания · начисления» (`.stat-cols`).
    На карточке у блоков «Услуги» и «Арендаторы» мелкая серая подпись КАПСОМ, справа от неё ссылка
    «✎ изменить» (или «+ добавить», если ещё пусто) — `.card-block-head`. Под «Услугами» — цифры
    (или плашка «Настройка»), под «Арендаторами» — список. На странице объекта слева — те же подписи, но у «Услуг» без «изменить»
    (услуги правятся тут же, в средней колонке; «+ добавить» — пока их нет).
    Такие ссылки — не жирные, акцентного цвета (`.setup-link`).
    После сохранения/удаления в окне — назад на ту страницу, откуда открыли (по Referer).
    Окно «Новая услуга» — одно (по образцу пользователя): под заголовком объект и арендаторы с долями;
    блоки «Что за услуга» (плитки-шаблоны: иконка над названием, все виды; уже добавленные — с галочкой),
    «Услуга» (Поставщик, Название в счёте арендатору), «Как считаем», «Как делим между арендаторами».
    Принцип окна — опрос: плитка-шаблон ставит все ответы по логике; вопрос да/нет — переключатель
    (`.switch` в forms.css, скрытое «0» + чекбокс «1»), выбор из вариантов — кнопки `.segmented`;
    следующий вопрос появляется только когда он нужен (CSS `:has`). «Как считаем»: «Есть счётчик?» →
    тариф и единица, иначе «Сумма» (разная / постоянная → поле суммы тут же). «Как делим»: по долям /
    поровну / по м² / по показаниям / плачу сам.
    Виды: Электричество, Вода холодная, Вода горячая, Вода горячая / подогрев, Водоотведение, Отопление,
    Газ, Содержание и ремонт, Капитальный ремонт, Вывоз мусора, Интернет, Своя (миграция 0005).
    Подогрев (Гкал) и водоотведение (= ХВС + ГВС) пока упрощены: по счётчикам, м³. Плашка перезагружает окно с полями по шаблону (`?kind=water`). Без шаблона
    выделена «Своя услуга». Плашки на странице объекта (пока услуг нет) открывают это окно с выбранным
    шаблоном. При изменении услуги плашек нет. Отдельного окна выбора вида больше нет.
- В работе ветка `feature/meters` (от `feature/add-service`, вливать после неё): счётчики.
  - Сделано (этап 1–2): `Meter` принадлежит объекту (`property`, `tenant` — чей, пусто = общий,
    `kind` — что меряет, `serial` — номер), услуга ссылается на счётчики `Receipt.meters` (многие-ко-многим),
    один счётчик может работать на несколько услуг (ХВС + водоотведение). Миграции 0006–0008 переносят
    старые счётчики с показаниями. `sync_meters` создаёт/отвязывает счётчики как раньше; счётчик,
    которым больше не пользуется ни одна услуга, удаляется (`drop_if_unused`, `delete_receipt`).
  - Сделано (этап 3, макет пользователя): блок «Как считаем» в окне услуги — список вопросов
    (`.calc-row`: подпись слева 150px, ответ справа, строки через тонкую линию). Переключатели —
    серая дорожка, выбранное — белая кнопка с тенью (`.seg-track`, так и в «Как делим»).
    «Счётчик: Да / Нет» → «Нет»: «Сумма квитанции: Каждый месяц разная / Фиксированная» (+ компактное
    поле суммы); «Да»: «Тариф: Однотарифный / День / ночь» + меню единицы `.pick` той же высоты,
    «Цена» (компактные поля `.ifield` с «день/ночь» и «₽ за кВт·ч» внутри рамки, обязательна),
    «Какие счётчики»: Общий на объект / У каждого свой / Общий + у каждого свой (`Receipt.layout`).
    Подсказку про смену тарифа не пишем. Ниже — тихий список «СЧЁТЧИКИ · ПОКАЗАНИЕ НА СТАРТЕ»:
    имя, плашка «+ № счётчика» (по нажатию — поле с ✓, зелёная рамка), показание справа (день и ночь).
    ✓ или уход из поля с номером → сохранён: синяя рамка (`--color-info`), ✎ открывает снова.
    «Как делим» показывается только при общем счётчике или без счётчика; кнопки «По показаниям» нет —
    это и есть «У каждого свой». При «Общий + свои» разница (общий − арендаторы) пока на собственнике.
  - Тариф меняется только в окне услуги (на странице объекта он лишь показан, с карандашом).
    Новый тариф — с текущего месяца: при смене старый записывается в прошлые месяцы с вводом
    (`MonthlyAmount.tariff`, `keep_past_tariffs`). Начальное показание счётчика — «было» его первого месяца.
    День/ночь: на странице объекта по две строки на счётчик (`prevn-`/`curn-`). Миграции 0009–0010.
  - Окно услуги (правки пользователя 2026-11-10): сверху шаблоны — компактные плашки (иконка + название,
    34px) в две короткие строки с переносом, без сворачивания (прокрутку в одну строку пробовали: половина
    шаблонов пряталась). Блок «Услуга» — только Поставщик и «Название в счёте». «Сколько стоит»: в одной
    строке «Счётчик Да/Нет» и рядом второй переключатель — без счётчика «Каждый месяц разная / Фиксированная»,
    со счётчиком «Однотарифный / День / ночь». Ниже «Сумма» (фиксированная — поле ввода; разная — такое же поле,
    неактивное, «вводится каждый месяц») или «Тариф [₽] за [кВт·ч ▾]». «Кто платит» плотнее, по порядку:
